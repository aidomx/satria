---help
Satria - A simple builder for you

> usage: satria [-f <file>] [-jN] <command>

(no command)           Build project from Buildfile
-f <file>              Use <file> as Buildfile (default: Buildfile)
-xf <build.ninja|make>  Convert build.ninja or Makefile -> Buildfile.xf.tmp
-xcf <build.ninja|make> Convert and write to Buildfile (confirm if exists)
-j[N]                  Parallel build with N jobs (default: CPU core count)
-g compdb              Generate compile_commands.json without building

satria init              Create a minimal Buildfile (use project)
satria init -p           Interactive scaffold (name, language, workspace)
satria init -w           Create Buildfile.ws (workspace template)
satria clean             Remove build artifacts
satria profile <ctx>     Measure operation costs (see: help profile)
satria trace [opts] -- <args>  Trace file access via LD_PRELOAD (see: help trace)
satria -w                Build all projects in workspace (Buildfile.ws)
satria -w <name>         Build <name> and its dependencies
satria -w release -- name=<p>[,key=value]  Package one release
satria watch [--full]   Monitor a background build (see: help watch)
satria -w watch [--full]  Same for a workspace background build
satria help              Show this help
satria help <topic>      Show topic help
satria version           Show version
satria self-upgrade      Upgrade satria itself
satria self-uninstall    Remove satria and global state (requires confirmation)

Topics: build, profile, workspace, init, clean, release, compdb, ninja, install, watch, trace
---endhelp

---build
Build commands

satria                   Build project from Buildfile
satria build             Same as above (explicit)
satria -f <file>         Build using <file> as the Buildfile
satria -j[N]             Parallel build, N jobs (-j1 = serial; no -j = cores)
satria -g compdb         Generate compile_commands.json only (no build)

Conventions for a standard project (src/ + optional include/):
  a one-line Buildfile is enough: `use project`

Buildfile fields that override conventions:
  sources, headers, flags, defines, std, compiler, exclude,
  output.binaryName, output.binaryDir, output.buildDir,
  output.libraryName, output.libraryShared

Platform/compiler suffixes on flags, library, headers, defines and
std (e.g. flags.linux, library.windows, defines.macos, std.gcc):
the global value applies first, matching suffix values are appended
with dedup; std.<target> overrides std.

Build is incremental: header tracking (mtime + content hash),
dependency cache (.satria/caches/deps.cache), and a fast no-op snapshot
(.satria/caches/fingerprint.cache) skip work when nothing changed.

Set `background = true` to run the build detached in the background
and monitor it with `satria watch` — see: help watch
---endbuild

---watch
Background build & watch (design/background.md)

Set `background = true` in Buildfile (or as a global line in
Buildfile.ws):

  use workspace
  background = true
  projects = app, tool

`satria` / `satria -w` then starts the build in a detached child
process and returns to the prompt immediately — exit code 0 means
"started successfully", not "build succeeded". Output goes to
.satria/background.log.

Files:
  .satria/build.pid          PID of the running build
  .satria/workspace.pid      ... in workspace mode
  .satria/background.log     stdout+stderr of the build (truncated on
                             each new background build)
  .satria/background.status  success | failed (written when finished)
  .satria/background.progress  "pct|activity" for the watcher

Commands:
  satria watch               Poll progress until the build finishes,
                             print the build summary, then exit
                             (0 = success, 1 = failed)
  satria watch --full        Stream background.log live (like tail -f),
                             summary appears at the end of the stream
  satria -w watch [--full]   Same for a workspace background build

Rules:
  - a second build is rejected while one is running:
      Error: Background build is already running (PID: N).
      Use 'satria watch' to monitor.
  - Ctrl+C inside watch only detaches the watcher; the build keeps
    running in its own session and can be re-attached anytime
  - `clean` is blocked while a background build is running
  - no-op runs (nothing to build) are answered inline by the
    router/fast-state path — no child is spawned
  - `satria watch` exits 0 on success, 1 on failure
---endwatch

---profile
Profile commands — measure costs without a normal build.
Profiling never touches build state (.satria/, Buildfile, artifacts).

satria profile archive=<dir> [with=tar|none|tar,gz|tar,xz|tar,bz2]
                       Measure tar + compression of a directory.
satria profile embed=<dir|file>
                       Measure embedded-asset pipeline.
satria profile library=<dir> [with=static|shared|static,shared]
                       Measure .o collection + ar rcs / cc -shared.
satria profile binary=<dir> [jobs=N] [--report <file>]
                       Measure full cold compile + link in isolation.
satria profile project=<dir> [jobs=N]
                       Measure the incremental project cycle:
                       config, fingerprint, decide, compile, link.
                       With --repeat 2 the second run shows the warm
                       path: decide > 0, compile = 0.
satria profile workspace=<dir>
                       Measure workspace model cost: parse,
                       dependency/topo, library-declaration checks.
                       Projects are validated but not built.

Options:
  with=<backend>       Context-specific; invalid combos are rejected:
                       "satria: profile option 'with' is not valid for
                       context '<ctx>'"
  jobs=N               (binary/project) parallel compile jobs
                       (default: cores)
  --report <file>      Write detailed report to file (summary stays
                       on the terminal)
  --repeat <N>         Repeat the run N times (1..100); the sandbox is
                       kept, so caches live and later runs measure the
                       warm path. Phases aggregate over all runs.

Output: terminal shows a short summary; piped output shows the
detailed report, so `satria profile archive=<dir> > profile.md` is
enough. Paths accept `~/...` (expanded by satria itself).

Examples:
  satria profile archive=rupamod with=tar,gz
  satria profile library=rupamod with=static,shared
  satria profile binary=. --report profile.md
  satria profile project=. --repeat 3
---endprofile

---workspace
Workspace commands (Buildfile.ws)

satria -w                Build (and release) every declared project
satria -w <name>         Build <name> and its dependency closure
satria -w clean          Clean the entire workspace
satria -w release -- name=<p>[,key=value]
                       Package one release to dist/release/<name>/
satria -w watch [--full] Monitor a background build (requires
                       `background = true`; see: help watch)
satria init -w           Create a workspace Buildfile (Buildfile.ws)

A minimal workspace Buildfile.ws:
  use workspace
  projects = app, tool

Members follow the standard convention (a <name>/ folder with
src/); per-project settings like <name>.sources or
<name>.depends_on are declared in the same file. Builds run in
two phases — library pass (lib<name>.a/.so) first, binary pass
after — so cross-project library references resolve correctly.
---endworkspace

---init
Init commands

satria init              Create a minimal Buildfile (just `use project`)
satria init -p           Interactive scaffold: project name, language
                       (c/cpp), std, compiler, flags, include/,
                       workspace membership, depends_on. Enter accepts
                       the default; the scaffold builds out of the box.
satria init -w           Write a workspace template (Buildfile.ws)

init never overwrites existing files: any existing target aborts
before writing. Ctrl+C or EOF cancels.
---endinit

---clean
Clean commands

satria clean             Remove build artifacts:
                         build directory (o.buildDir, default build/)
                         bin directory (o.binaryDir, default bin/)
                         lib directory (o.libDir, default lib/)
                         compile_commands.json
                         .satria cache (deps.cache, build state)

Clean follows the active project configuration; in workspace mode
(`satria -w clean`) it cleans every member project.

While a background build is running (`background = true`), clean is
blocked so artifacts cannot be removed mid-build — wait for it or
check with `satria watch` (see: help watch).
---endclean

---release
Release commands (workspace)

satria -w release -- name=<project>[,key=value...]
                       Package one project release from the CLI.
                       name= is required; target=deb|tar overrides the
                       packaging format for this run. Artifacts go to
                       dist/release/<name>/ (or dist/release/ for a
                       full `satria -w` run).

Releases can also be declared in Buildfile.ws:
  releases = rupa, ruka
  releases.rupa as rrupa
  rrupa.name = rupa
  rrupa.target = deb

Packages need pack.files (source:path mapping); checksum
sha256 is written next to the artifact when enabled.
---endrelease

---compdb
Compile commands

satria -g compdb         Generate/refresh compile_commands.json without
                       building. Query-only: safe to run any time
                       (editor/clangd integration).

Buildfile: output.compileCommands = auto (default) avoids
rewriting the file when configuration is unchanged.
---endcompdb

---ninja
Ninja conversion

satria -xf <build.ninja>
                       Convert a Ninja build file to a Buildfile and
                       write it to Buildfile.xf.tmp (temporary; the
                       existing Buildfile is never touched). The temp
                       file is used for this command and removed
                       afterwards.
satria -xcf <build.ninja>
                       Same conversion, but writes the result to
                       Buildfile — with a confirmation prompt first if
                       one already exists.

Makefile conversion

satria -xf make          Search Makefile/makefile/GNUmakefile in the
                       current directory, extract declarative config
                       (compiler, std, flags, defines, headers,
                       library, sources, target) and write
                       Buildfile.xf.tmp.
satria -xcf make         Same, but writes to Buildfile (confirmation
                       prompt if one exists).

Makefile conversion is declarative extraction: only static config is
captured; procedural logic (ifeq, $(MAKE), $(shell)) is ignored and
flagged with a warning comment in the output.

Conversion is best-effort for common Ninja rules; the converted
Buildfile may need edits for non-standard setups.
---endninja

---trace
Trace file access (POSIX, LD_PRELOAD)

  satria trace [--out FILE] [--top N] [--so FILE] [--] <args satria>

Runs satria with a tracer that logs each open/stat/access/... call of the
process and its children, then prints a summary (same as
`sort log | uniq -c | sort -rn | head`).

  satria trace -- -w core       Trace a workspace build of `core`
  satria trace --top 50 -- -w   Show the 50 most frequent accesses

Options must come before the satria arguments. The first token that is not
a trace option starts the arguments for satria.

Tracer: the source is built into satria itself. On each run satria writes
.satria/trace/openat_trace.c and compiles .satria/trace/openat_trace.so with
`cc` (env CC, default cc), but only when the source changed or the .so is
missing. No external files are needed.
Use --so FILE to supply a prebuilt tracer (for example for another arch).

Log: .satria/trace/openat.log (or --out). Each run starts a new log.
Child processes (gcc, ld, ar) inherit the tracer, so their accesses are
included; the summary is not filtered by process.

Not supported on Windows (uses LD_PRELOAD/dlsym).
---endtrace
