## Jalur lama

Jalur lama masih ada bukan digunakan hanya untuk fallback.

Saat ini masih menghasilkan :
```text
.satria:
caches                  sources.cache
compile_commands.blob   startup.state
compile_commands.cache  workspace
ld.cache                workspace_log
opts.cache              workspace.state
pack

.satria/caches:
deps.cache  embed.cache  lib.cache

.satria/pack:

.satria/workspace:
bade.build.fingerprint  core.build.fingerprint
bade.src                core.src
bade.ws.state           core.ws.state
```

terutama `.satria/workspace` ini masih dihasilkan, padahal tujuan membuat jalur baru itu untuk menggantikan jalur lama.

Hasil yang diharapkan :
```text
.satria:
D caches
F sources.cache
F compile_commands.blob
F compile_commands.cache
F ld.cache
F build.log
F opts.cache              
F startup.state
D pack

.satria/caches:
F fingerprint.cache
F deps.cache
F embed.cache
F lib.cache

.satria/pack:
```

## `opts.cache` sebagai jalur utama :

digunakan untuk create, read, update, delete karena sudah berisi alamat lengkap, ini adalah router utama di `design/startup.md` harusnya sudah tertulis.

create = cold
create = add new file
read = jika tanpa ada perubahan apapun (no-op)
update = edit file, edit header, edit module
delete = file yang dihapus, alamat yang tersimpan dihapus.

Ini hanya gambaran sederhananya, untuk kinerja saat ini sudah sangat komplit dan bekerja dengan baik hanya belum maksimal saja.

Alur `opts.cache` ringkas (implementasi nyata tentu lebih kompleks) :

opts.cache -> sources.cache -> caches/

Sebagai gambaran jika di web (hanya contoh):
```
app.get("/", sources)
app.post("/core", sources.core)
```

Tentu yang bekerja adalah sources, tugas `opts.cache` hanya sebagai router.

`sources.cache` juga akan memperbarui `opts.cache` karena saling terikat.

Lalu bagaimana agar jalur no-op bisa super cepat?

Ambil contoh di `.satria/caches/deps.cache` ada :
`P <alamat>`
Ini tidak cukup karena tetap perlu membaca seluruh alamat yang tersimpan dan tidak menguntungkan di no-op.

`P <alamat> <content> <time> <size>`

Ini memungkinkan `sources.cache` tidak perlu membaca terlalu dalam jika tidak ada perubahan sama sekali.
